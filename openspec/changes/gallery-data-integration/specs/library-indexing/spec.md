## ADDED Requirements

### Requirement: 截图枚举以目录为主

系统 MUST 以目录枚举作为截图发现的唯一权威来源，VDF 索引只能补充元数据。

#### Scenario: 索引缺失但文件存在
- **WHEN** 某张截图存在于 `screenshots` 目录但不在 `screenshots.vdf` 中
- **THEN** 该文件仍然被索引入库，并标记其时间来源为文件时间

#### Scenario: 排除缩略图
- **WHEN** 枚举某游戏的截图目录
- **THEN** `thumbnails` 子目录下的文件不计入原图数量与体积，只作为缩略图来源

#### Scenario: 只处理受支持的图片扩展名
- **WHEN** 目录中存在非图片文件
- **THEN** 该文件被跳过，不计入统计，也不导致扫描失败

### Requirement: 内容指纹与逻辑去重

系统 MUST 为每张原图计算完整 SHA-256，并 MUST 按 `(accountKey, gameKey, sha256)` 作为逻辑身份。

#### Scenario: 同游戏内内容完全相同
- **WHEN** 同一账号同一游戏下存在字节完全相同的多个文件
- **THEN** 它们归为同一逻辑资产，图片数只计一次，但保留每一条来源文件记录

#### Scenario: 同内容跨游戏
- **WHEN** 相同字节的截图出现在两个不同游戏下
- **THEN** 保留两份独立的逻辑资产归属，不合并计数

#### Scenario: 同画面不同编码
- **WHEN** 两个文件画面相同但字节不同（例如 JPG 与高质量副本）
- **THEN** 它们是不同资产，都完整保留

### Requirement: 扫描进度与取消

系统 MUST 提供扫描进度，MUST 支持取消，MUST NOT 伪造百分比。

#### Scenario: 进度上报
- **WHEN** 扫描进行中
- **THEN** 进度包含阶段、已处理数量与总量；总量未知时该字段为空而不是编造数字

#### Scenario: 取消扫描
- **WHEN** 用户在扫描过程中取消
- **THEN** 扫描在文件边界停止，已入库的数据保留，来源文件不受影响

#### Scenario: 单个文件读取失败
- **WHEN** 某个文件无法读取或哈希失败
- **THEN** 记录该文件失败并继续其余文件，扫描结束时给出失败明细数量

### Requirement: 重复扫描幂等

系统 MUST 保证重复扫描不产生重复行与重复计数。

#### Scenario: 再次扫描同一来源
- **WHEN** 对同一来源重复执行扫描
- **THEN** 资产与来源文件按唯一键更新而不是新增，图片数与统计保持不变

#### Scenario: 来源文件消失
- **WHEN** 上次扫描存在的文件在本次扫描中不存在，且该来源本次扫描成功
- **THEN** 对应来源文件被标记为不存在，资产记录保留，不删除任何行

#### Scenario: 来源本次扫描失败
- **WHEN** 来源目录本次不可达
- **THEN** 不更新任何文件的存在状态，避免把不可达误判为删除
