## MODIFIED Requirements

### Requirement: 预览缓存

系统 MUST 为图库资产生成中等尺寸预览，MUST NOT 在图片请求里同步生成（避免阻塞界面）。
预览 MUST 至少提供两种尺寸：卡片用的预览与缩略图带用的迷你图。
预览生成完成后 MUST 主动通知渲染层，使已显示的图片可以自动换成预览。

#### Scenario: 请求缩略图
- **WHEN** 渲染层请求某资产的缩略图
- **THEN** 优先返回自建预览；没有预览时返回来源缩略图；都没有时返回原图，并把该资产放入后台队列

#### Scenario: 预览就绪后自动替换
- **WHEN** 后台队列为某张已经显示在界面上的图生成了预览
- **THEN** 系统通知渲染层，该图重新请求并换成预览（清晰且体积更小）

#### Scenario: 一屏大量图片同时缺预览
- **WHEN** 一屏有数百张图都还没有预览
- **THEN** 系统 MUST NOT 用 4K 原图兜底（会触发解码风暴），MUST NOT 在图片请求里同步生成预览（会把请求与界面一起拖死），而是先返回来源缩略图，再把该资产**插到队首**由后台队列生成并自动替换

#### Scenario: 可见图片的排队优先级
- **WHEN** 用户正在浏览的图片还没有预览，而此时队列里已有大量后台预热任务
- **THEN** 这些可见图片 MUST 排在预热任务之前处理

#### Scenario: 归档后预热
- **WHEN** 一次归档完成且图库中仍有缺预览的资产
- **THEN** 这些资产被放入后台队列，由限速队列逐步生成

#### Scenario: 队列不得占满主进程
- **WHEN** 队列连续生成预览
- **THEN** 每张之间按实测解码耗时让出相应时间（约 50% 占用），保证图片请求与界面仍能及时响应

#### Scenario: 源文件不可解码
- **WHEN** 源文件损坏或格式不被支持
- **THEN** 该资产记为失败且不写入缓存文件，界面继续回退到来源缩略图或原图

#### Scenario: 缓存可重建
- **WHEN** 预览缓存被删除
- **THEN** 系统不报错，浏览时重新生成
