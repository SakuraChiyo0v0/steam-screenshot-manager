# Steam Screenshot Manager

一个优先在本地运行的 Steam 截图管理应用：自动发现多个账号与多款游戏的截图，按游戏整理和统计，把原件归档进独立图库，备份到你自己的 WebDAV，并能在新电脑上恢复。

## 功能

- **发现与索引**：从注册表或手动指定目录找到 Steam 安装位置，读取账号与游戏信息，扫描截图目录并建立本地索引，逐张计算 SHA-256。
- **图库浏览**：按游戏查看、搜索与筛选、按拍摄时间排序、等比例浏览，滚动到底自动加载更多；大图查看支持方向键切换、原始大小与 Esc 返回。
- **独立图库归档**：把原件复制进你自己的图库目录，复制过程中校验指纹，来源目录只读。
- **按规则导出**：按游戏名／年份／AppID 组织目录导出，处理 Windows 非法字符与重名冲突（冲突保留两份，不覆盖）。
- **WebDAV 备份**：上传后读回校验内容，全部通过才算备份完成；支持中断续跑、失败重试与限流退避。
- **换机恢复**：连接同一个远端图库，读取清单、按游戏把截图恢复到本机，并逐张校验。
- **日常使用**：后台按间隔自动收集、系统托盘、关闭窗口留在托盘、开机自启。
- **预览缓存**：自动生成 1000px 预览（没设图库目录时缓存在用户数据目录），浏览大量图片时不必反复解码 4K 原图。

## 范围与边界

首版面向 **Windows x64**，技术栈为 Electron + TypeScript + React + 本地 SQLite（使用 Electron 内置的 `node:sqlite`，没有原生模块）。

首版不做：Steam 登录、在线完整游戏库、Linux/Steam Deck、NAS 网页图库、存档与游戏安装包、录像、公开分享、多用户服务、端到端加密、云端永久删除。恢复图片到普通目录，不承诺重建 Steam 自带截图管理器的索引。

## 不可破坏的约束

- Steam 来源只读：复制原件，不移动、不覆盖、不重压缩，不修改 Steam 的 VDF。
- 原始字节完整保存；缩略图是可丢弃缓存，JPG 与高质量版本不会自动互相替代。
- 本机文件消失不传播远端删除；首版没有跨端永久删除，也没有自动清理无引用对象。
- 同名不同内容不覆盖；相同账号、游戏、内容指纹按同一张图片统计。
- 完整性校验通过才显示对应完成状态；上传请求成功不等于远端已校验。
- SQLite 只在本机使用，不作为多设备同步媒介。
- 密码、访问令牌、设备绝对路径不进入远端清单、普通日志或诊断包。
- 无网络、无 API key、游戏名未知时，仍然能保存本地截图。

## 状态与限制

当前版本 **0.4.0**，变更见 [更新日志](CHANGELOG.md)。核心链路（索引 → 归档 → 备份 → 恢复）已实现，并有单元测试与本地端到端验证。

已知限制：

- WebDAV 备份与恢复已在自建 NAS 的 WebDAV 上验证（经本机端口镜像接入），未在其他第三方服务上验证。
- 未安装且本机没有名称来源的游戏会显示为「未知游戏（AppID）」。
- 本机删除不会传播到远端；双向同步与冲突处理尚未实现，破坏性批量操作也未提供。
- 重复上传留下的远端旧对象暂无自动清理策略（恢复端按内容指纹去重，不受影响）。

## 开发与运行

环境要求：Node.js ≥ 22.12、pnpm 11.15（版本写在 `package.json` 的 `packageManager`）。

| 命令 | 作用 | 说明 |
|---|---|---|
| `pnpm install` | 安装依赖 | 依赖的构建脚本在 `pnpm-workspace.yaml` 里逐项声明放行与否 |
| `pnpm dev` | 开发运行 | 渲染层热更新；界面打开的即图库 UI |
| `pnpm typecheck` | 类型检查 | 主进程/预加载与渲染层两份配置分别检查 |
| `pnpm test` | 单元测试 | Vitest；覆盖迁移、事务、路径校验、设备 ID、IPC 契约、归档与恢复 |
| `pnpm build` | 构建 | 产物在 `out/`（主进程与预加载为 CommonJS） |
| `pnpm self-check` | 构建后自检 | 在真实 Electron 运行时里写库读回并探测渲染层边界，报告写入用户数据目录的 `self-check.json` |
| `pnpm package` | 打包 | Windows 安装包与便携版输出到 `release/` |
| `pnpm package:dir` | 免安装打包 | 只产出 `release/win-unpacked/`，用于快速验证 |

运行时事实：

- **SQLite 使用 Electron 内置的 `node:sqlite`**，没有原生模块，也不需要 `electron-rebuild`。
- 应用数据位于 Electron 用户数据目录（Windows 为 `%APPDATA%\steam-screenshot-manager`），内含 `app.sqlite3`、`device.json`；图库与预览缓存放在用户选择的图库目录。真实图片与凭据不写入安装目录或源码目录。
- `.npmrc` 里的 `electron_mirror` 指向 npmmirror，便于在直连 GitHub Releases 较慢的网络环境安装；网络条件更好时可以删掉该项回到默认源。

## 项目结构

```
src/
  core/        领域逻辑：Steam 发现与扫描、图库索引与查询、归档、导出、WebDAV 上传与恢复、数据库迁移与设置
  main/        主进程：窗口、IPC、自定义图片协议、各类任务编排（扫描/归档/导出/上传/恢复）、托盘
  preload/     上下文隔离下的白名单桥接
  renderer/    React 界面：图库、查看器、同步中心、设置
  shared/      主进程与渲染层共用的类型、IPC 契约与纯函数
tests/         单元测试
openspec/      变更提案与能力规格
```
