# Steam Screenshot Manager

一个优先在本地运行的 Steam 截图管理应用：自动发现截图，按游戏整理和统计，将原件备份到用户自己的 WebDAV，并在新电脑恢复。

## 核心目标

1. 提取本机多个 Steam 账号、多个游戏的截图，支持高质量副本和手动补充目录。
2. 游戏列表、截图浏览、数量与体积统计、按规则导出。
3. 绑定标准 WebDAV，同步新增图片并可靠校验；不依赖 NAS、自建业务服务或 Steam 登录。
4. 新电脑只需连接同一远端图库，即可恢复选定游戏的截图，不依赖旧电脑仍在线。

## 首版边界

首版面向 Windows x64，采用 Electron、TypeScript、React、本地 SQLite。React 是界面实现建议；Electron、TypeScript、本地 SQLite 是已确认约束。先完成离线采集和图库，再接 WebDAV，最后补后台可靠性。

Steam 登录、在线完整游戏库、Linux/Steam Deck、NAS 网页图库属于后续增强。首版不做存档、游戏安装包、录像、公开分享、多用户服务、端到端加密或云端永久删除。恢复图片到普通目录，不承诺自动恢复 Steam 自带截图管理器的索引。

实测该生活机上已存在 **44.6 GB Steam 录屏与剪辑数据**，属于首版范围外，仅记录在真实数据快照，不因此扩大首版。

## 开发与运行

环境要求：Node.js ≥ 22.12、pnpm 11.15（版本写在 `package.json` 的 `packageManager`）。

| 命令 | 作用 | 说明 |
|---|---|---|
| `pnpm install` | 安装依赖 | 依赖的构建脚本在 `pnpm-workspace.yaml` 里逐项声明放行与否 |
| `pnpm dev` | 开发运行 | 渲染层热更新；默认打开图库 UI，原 启动自检在设置 → 工程诊断 |
| `pnpm typecheck` | 类型检查 | 主进程/预加载与渲染层两份配置分别检查 |
| `pnpm test` | 单元测试 | Vitest，覆盖迁移、事务、路径校验、设备 ID、IPC 契约 |
| `pnpm build` | 构建 | 产物在 `out/`（主进程与预加载为 CommonJS） |
| `pnpm self-check` | 构建后自检 | 在真实 Electron 运行时里写库读回并探测渲染层边界，报告写入用户数据目录的 `self-check.json` |
| `pnpm package` | 打包 | Windows 安装包与便携版输出到 `release/` |
| `pnpm package:dir` | 免安装打包 | 只产出 `release/win-unpacked/`，用于快速验证 |

运行时事实（工程基础阶段 实测）：

- **SQLite 使用 Electron 内置的 `node:sqlite`**，没有任何原生模块，也不需要 `electron-rebuild`。
- 应用数据位于 Electron 用户数据目录（Windows 为 `%APPDATA%\steam-screenshot-manager`），
  内含 `app.sqlite3`、`device.json`、`logs/`。真实图片与凭据不写入安装目录或源码目录。
- `.npmrc` 里的 `electron_mirror` 指向 npmmirror：本机实测直连 GitHub Releases 长时间无进展，
  换镜像后约 4.7 MB/s。网络条件更好的环境可以删掉该项回到默认源。

## 不可破坏的约束

- Steam 来源只读：复制原件，不移动、覆盖、重压缩，不修改 Steam 的 VDF。
- 原始字节完整保存；缩略图是可丢弃缓存，JPG 和高质量版本不自动互相替代。
- 本机文件消失不传播远端删除。首版没有跨端永久删除和自动清理无引用对象。
- 同名不同内容不覆盖；相同账号、游戏、内容指纹按同一图片统计。
- 完整性验证通过才显示对应完成状态；上传请求成功不等于远端已校验。
- SQLite 只在本机使用，不把数据库文件当作多设备同步媒介。
- 密码、访问令牌、设备绝对路径不进入远端清单、普通日志或诊断包。
- 无网络、无 API key、游戏名未知时，仍然能保存本地截图。

## 交付与审核

每个阶段更新任务状态，并提交一份 Markdown 实施报告：改动摘要、实际执行的命令与结果、未验证项、已知风险。完整模板见实施计划。没有证据不得将阶段标为通过。

最终审核重点是“电脑 A 采集 → WebDAV 保存 → 干净环境 B 重建 → 每个原件哈希一致”，并检查同名冲突、误删隔离和断网恢复。两套隔离用户数据目录只能证明逻辑隔离恢复；声称跨机器验证需要两台机器的证据。
