# Steam Screenshot Manager

一个优先在本地运行的 Steam 截图管理应用：自动发现多个账号与多款游戏的截图，按游戏浏览与统计，并 **一键双向同步** 到你自己选的备份地址——可以放在本机、NAS 共享或 WebDAV，也可以同时配多个。

## 功能

- **发现与索引**：从注册表或手动指定目录找到 Steam 安装位置（目录选择支持一次选多个），读取账号与游戏信息，扫描截图目录并建立本地索引，逐张计算 SHA-256。
- **一键同步（双向）**：点一次完成三步——① 推：扫描 Steam 来源，把新截图写到**每个**备份地址；② 收：把备份里有、本机没有的取回来；③ 写回：把本机有、Steam 里缺的登记回 Steam（Steam 在运行时会跳过这一步）。
- **多个备份地址**：本机盘、NAS 共享、WebDAV 可以混搭，各自记录进度；某个地址取不到只跳过它，不影响其它地址。连接前可以直接浏览远端目录，不用手拼路径。
- **图库浏览**：按游戏查看、搜索与筛选、按拍摄时间排序、等比例浏览，滚动到底自动加载更多；大图查看支持方向键切换、原始大小与 Esc 返回。
- **按规则导出**：按游戏名／年份／AppID 组织目录导出，处理 Windows 非法字符与重名冲突（冲突保留两份，不覆盖）。
- **备份校验**：上传后读回核对指纹，全部通过才算备份完成；支持中断续跑、失败重试与限流退避。
- **日常使用**：后台按间隔自动同步、系统托盘、关闭窗口留在托盘、开机自启。
- **预览缓存**：自动生成 1000px 预览，浏览大量图片时不必反复解码 4K 原图。

## 范围与边界

面向 **Windows x64**，技术栈为 Electron + TypeScript + React + 本地 SQLite（使用 Electron 内置的 node:sqlite，没有原生模块）。

同步只做**并集**：任何一边少了都不会删除另一边，也没有「删除同步」或破坏性批量操作。写回 Steam 会修改 Steam 自己的截图登记，因此要求 Steam 完全退出；推与收只读写 Steam 来源与备份地址。

首版不做：Steam 登录、在线完整游戏库、Linux/Steam Deck、NAS 网页图库、存档与游戏安装包、录像、公开分享、多用户服务、端到端加密、云端永久删除。

## 不可破坏的约束

- Steam 来源**只读**；只有显式写回 Steam 时，在客户端完全退出后新增截图并合并索引，写前备份，已有文件不覆盖，原图不重压缩。
- 原始字节完整保存；缩略图与预览是可丢弃缓存，JPG 与高质量版本不会自动互相替代。
- 本机文件消失不传播删除，反之亦然；同步与恢复都可随时重复执行。
- 同名不同内容不覆盖；相同账号、游戏、内容指纹按同一张图片统计。
- 完整性校验通过才显示对应完成状态；上传请求成功不等于远端已校验。
- SQLite 只在本机使用，不作为多设备同步媒介。
- 密码、访问令牌、设备绝对路径不进入远端清单、普通日志或诊断包。
- 无网络、无 API key、游戏名未知时，仍然能保存本地截图。

## 状态与限制

当前版本 **0.15.0**，变更见 [更新日志](CHANGELOG.md)。核心链路（发现 → 索引 → 一键双向同步 → 校验 → 写回 Steam）已实现，并有单元测试与真机验证。

已知限制：

- 备份与恢复在自建 NAS 上验证（WebDAV 经本机端口镜像接入，以及 SMB 映射盘作为文件夹地址），未在其他第三方服务上验证。
- 未安装且本机没有名称来源的游戏会显示为「未知游戏（AppID）」。
- 重复上传留下的远端旧对象暂无自动清理策略（恢复端按内容指纹去重，不受影响）。
- 写回 Steam 首期仅支持本机同账号的普通 JPEG，不承诺恢复社区状态或完整原始元数据；详见 [验证与使用说明](docs/steam-restore-pilot.md)。

## 开发与运行

环境要求：Node.js ≥ 22.12、pnpm 11.15（版本写在 package.json 的 packageManager）。

| 命令 | 作用 | 说明 |
|---|---|---|
| `pnpm install` | 安装依赖 | 依赖的构建脚本在 `pnpm-workspace.yaml` 里逐项声明放行与否 |
| `pnpm dev` | 开发运行 | 渲染层热更新 |
| `pnpm typecheck` | 类型检查 | 主进程/预加载与渲染层两份配置分别检查 |
| `pnpm test` | 单元测试 | Vitest；覆盖迁移、事务、路径校验、设备 ID、IPC 契约、同步与恢复、远端目录解析 |
| `pnpm build` | 构建 | 产物在 `out/`（主进程与预加载为 CommonJS） |
| `pnpm self-check` | 构建后自检 | 在真实 Electron 运行时里写库读回并探测渲染层边界，报告写入用户数据目录的 `self-check.json` |
| `pnpm package` | 打包 | Windows 安装包与便携版输出到 `release/` |
| `pnpm package:dir` | 免安装打包 | 只产出 `release/win-unpacked/`，用于快速验证 |

运行时事实：

- **SQLite 使用 Electron 内置的 node:sqlite**，没有原生模块，也不需要 electron-rebuild。
- 应用数据位于 Electron 用户数据目录（Windows 为 `%APPDATA%\steam-screenshot-manager`），内含 `app.sqlite3`、`device.json` 与可选的本地缓存；真实图片与凭据不写入安装目录或源码目录。
- 备份地址支持两类：**文件夹**（本机盘、NAS 共享、已映射的网络盘）与 **WebDAV**（含入口前缀自动识别）。
- `.npmrc` 里的 `electron_mirror` 指向 npmmirror，便于在直连 GitHub Releases 较慢的网络环境安装；网络条件更好时可以删掉该项回到默认源。

## 项目结构

```
src/
  core/        领域逻辑：Steam 发现与扫描、索引与查询、导出、同步（远端客户端 / 记录格式 / 上传 / 恢复）、数据库迁移与设置
  main/        主进程：窗口、IPC、自定义图片协议、任务编排（扫描/备份/恢复/一键同步）、托盘
  preload/     上下文隔离下的白名单桥接
  renderer/    React 界面：图库、查看器、同步中心、设置
  shared/      主进程与渲染层共用的类型、IPC 契约、错误文案与纯函数
tests/         单元测试
openspec/      变更提案与能力规格
```
